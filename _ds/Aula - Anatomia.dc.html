Aula — quatro conteúdos, uma casca

Uma tela que despacha por formato: vídeo, PDF, texto e imagem ou prova. O que muda é o miolo do card; cabeçalho, largura e o par selo/botão de conclusão são os mesmos. Especificação componente por componente, lida de classroom/lesson.blade.php e dos quatro parciais em classroom/partials/.

O que a tela faz

Consumir o conteúdo
Vídeo do YouTube, PDF embutido, texto com imagem, ou o encaminhamento para a prova.
Registrar progresso
No vídeo, automático: o tempo assistido é enviado a cada 5 segundos e a aula conclui aos 90%.
Marcar como concluída
Em PDF e em texto, a conclusão é manual: um botão que desaparece e dá lugar ao selo.
Ordem do despacho
quiz tem prioridade sobre qualquer youtube_url ou pdf_path perdido. Dado malformado nunca cai num player concluível.
Prova não conclui aqui
Aula de prova não tem botão de conclusão: quem conclui é a submissão da prova, com completion_source = quiz_passed.
Voltar
Um botão de volta à sala de aula no cabeçalho, dusk="back-to-classroom".

Regra 1
Coluna de leitura de 880px para mídia e 760px para texto corrido. Player mais largo que isso não melhora nada e desalinha o cabeçalho.
Regra 2
O selo e o botão são escondidos por classe, não pelo atributo hidden. É contrato com o JS existente — ver bloco 07.
Regra 3
Vídeo indisponível é aviso cinza com o que fazer. Não é warning amarelo e não culpa o aluno.

Aula em vídeo

video-player-{id}contrato rígido

Caixa 16:9 em fundo escuro, com um <iframe> de fallback que o LessonPlayer.js substitui pelo player da API do YouTube. A proporção mora no wrapper externo, nunca no elemento marcado — porque a API troca esse elemento por um iframe próprio, e o dimensionamento tem que sobreviver à troca. Sem vídeo reconhecível, a caixa 16:9 não é renderizada e entra um aviso em fluxo normal.

O que não pode mudar
A proporção fica fora. A caixa 16:9 é o wrapper; o nó [data-youtube-player] é substituído pela API. Regra CSS: .ds-ratio > * dimensiona o que estiver no slot.
Um só nó com o dusk. video-player-{id} está no mesmo elemento nos dois ramos do @if. Nunca duplique entre os ramos.
Os quatro data-* andam juntos: data-youtube-player, data-lesson-id, data-video-id, data-progress-url — todos no mesmo nó, e só quando há vídeo reconhecido.
O iframe de fallback permanece. É o que funciona sem JS e antes de a API assumir. Mantenha allow, allowfullscreen e os parâmetros rel=0&modestbranding=1&controls=1.

Aula do tipo prova não mostra conteúdo: mostra o encaminhamento. 07

Barra de conclusão

lesson-completed-badgemark-complete-buttoncontrato rígido

Selo e botão vivem no mesmo par em três dos quatro formatos, e são alternativos: um está visível quando o outro está escondido. Quem alterna é o LessonPlayer.js, trocando uma classe utilitária — e é aqui que está a armadilha desta tela.

Nunca use o atributo hidden nestes dois elementos. O Reboot do Bootstrap emite [hidden] { display: none !important }, uma regra de autor que vence qualquer style.display que o JS escreva para revelar o elemento — o selo simplesmente não apareceria. O estado escondido é uma classe, alternada por classList. Na casca nova, troque .d-none por uma classe própria (por exemplo .ds-hidden) e ajuste o JS junto, na mesma tarefa. Se sair o Bootstrap, a regra !important vai com ele — mas o padrão de classe permanece, porque é o que o JS manipula.
